They are HTTP request methods (also commonly called HTTP verbs).

When you use GET, the data is pasted right on the outside of the envelope for everyone to see. When you use POST, the data is sealed inside the envelope.

GET is a Postcard: The mail carrier, the sorting facility workers, and anyone looking at your desk can read what is written on it.

POST is a Sealed Letter: People can see who it is addressed to (the URL), but they have to tear open the envelope to see the message inside.

GET - read only

POST - write and modify the data 

# =================================================================================
#                         HTTP METHODS MASTER REFERENCE
# =================================================================================

Method   CRUD Action   Database Op      Safe?* Idempotent?** Privacy Level
------   -----------   -----------      ------   -------------   -------------
GET  --> READ      --> Fetch/Select     YES      YES             LOW (Postcard)
POST --> CREATE    --> Insert Record    NO       NO              HIGH (Sealed)
PUT  --> UPDATE    --> Replace Record   NO       YES             HIGH (Sealed)
PATCH--> UPDATE    --> Partial Modify   NO       NO*** HIGH (Sealed)
DELETE-> DELETE    --> Remove Record    NO       YES             HIGH (Sealed)

# ---------------------------------------------------------------------------------
# FOOTNOTES & DEFINITIONS:
# ---------------------------------------------------------------------------------
# * Safe?       = Does it promise NEVER to alter/modify database data?
# ** Idempotent? = Does repeating the exact same request yield the same DB state?
# *** PATCH note = Can be non-idempotent depending on logic (e.g., {"age": "age+1"}).
# =================================================================================

function countCharacters(s) {
    // 1. FRESH CONTAINER
    // Defining inside the function so it flushes/resets for every new input string.
    // We use an object literal because it acts as a dictionary to hold key-value pairs.
    let result = {};  

    // 2. THE ITERATION
    for (let item of s) {
        
        // IMPORTANT SYNTAX: Check if the counter for that particular char already exists
        if (result[item]) {
            // If character exists, increment its unrelated independent count
            result[item] = result[item] + 1;
        } 
        else {
            // If character is seen for the first time, initialize it to 1
            result[item] = 1;
        }
    }

    return result;
}

# THE COMPLETE, UNFILTERED DATA PIPELINE: 
# SQL Database -> Python Server -> Browser (JavaScript Object)


# 1. THE TRUTH ABOUT THE RELATIONSHIP:
# A SQL Database and a JavaScript Object never talk directly to each other. 
# They live in completely different worlds, speak completely different languages, 
# and reside on different machines. 
# Your Python Server (Flask) acts as the multilingual translator in the middle.


# 2. THE DATA TRANSFORMATION TIMELINE:

# STEP A: THE SQL DATABASE (The Warehouse)
# - Data lives as raw tables (rows/columns) on the storage disk.
# - Database spits out a raw row tuple: (101, "Diyaa")

# STEP B: THE PYTHON SERVER / FLASK (The Translator)
# - Flask catches that raw tuple using its database driver.
# - Flask converts that tuple into a Python Dictionary: {"id": 101, "name": "Diyaa"}
# - Flask serializes (converts) that dictionary into a raw JSON text string: '{"id": 101, "name": "Diyaa"}'
# - Flask spits that JSON string over the network network to the browser.

# STEP C: THE BROWSER / JAVASCRIPT (The End User)
# - The browser receives the raw JSON text string.
# - JavaScript parses (translates) that text string back into a native JavaScript Object: { id: 101, name: "Diyaa" }
# - JS can now dynamically manipulate the UI with it.


# 3. THE COMPLETE VISUAL STREAM PIPELINE:
"""
  [ SQL ENGINE ]                   [ SERVER (FLASK) ]                    [ BROWSER (JS) ]
┌────────────────┐               ┌────────────────────┐                ┌────────────────┐
│  Raw Rows/Cols │               │ Transformed into   │                │ Text parsed into│
│    (Tables)    │               │ Python Dict, then  │                │   Native JS    │
│                │               │ serialized to JSON │                │    Object      │
└────────────────┘               └────────────────────┘                └────────────────┘
        │                                   │                                   │
        └───(Raw Tuple: (101, "Diyaa"))────>│                                   │
                                            └───(JSON String: '{"id":101...}')─>│
                                                                                └──> {id:101}
"""
