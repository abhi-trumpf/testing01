SECTION 1: C# RULES & SYNTAX NOTES
(How to write the code correctly so it doesn't crash)
1. Spelling and Capital Letters (C# is very strict)
•	.Length $\rightarrow$ Always use a capital L. Never put brackets after it like .Length(). It counts things in any array (int[], char[]), not just words.
•	Console.ReadLine() $\rightarrow$ Capital C, R, and L. This is used to take what the user types.
•	Console.Write() vs Console.WriteLine() $\rightarrow$ Capital C, W, and L.
o	Console.Write() prints text and keeps the typing cursor on the same line.
o	Console.WriteLine() prints text and moves the cursor to the next line.
•	HashSet $\rightarrow$ Always capitalize the S (HashSet<int>).
•	Main $\rightarrow$ The starting point of your program must be written exactly like this: public static void Main(string[] args). The M must be capital, and the square brackets [] go right next to the word string.
2. Simple Text & Math Rules
•	No let keyword $\rightarrow$ You cannot use let like in JavaScript. You must say the real type, like int rem = 0;.
•	String Interpolation ($"") $\rightarrow$ Putting a $ before your text lets you inject variables, but only if you put curly braces {} around the variable name.
o	Wrong: Console.WriteLine($"lcm is", max); (This completely ignores max).
o	Right: Console.WriteLine($"lcm is {max}");
•	Modulo Math Reminder $\rightarrow$ When you divide a smaller number by a bigger number using %, the answer is just the smaller number itself (Example: 1 % 10 = 1).
3. Working with Arrays and Lists
•	The Big Difference:
o	An Array (int[]) is a fixed size. Once you make it, you cannot grow it. You cannot use shortcuts like .Add() or .Remove().
o	A List (List<T>) is dynamic. It can grow and shrink whenever you want. You must write using System.Collections.Generic; at the top of your file to use it.
•	Making Arrays (New vs Old C#):
o	C# 12 or newer: You can use clean square brackets: int[] arr = [1, 2, 3];.
o	C# 11 or older: You must use curly braces: int[] arr = {1, 2, 3}; or new int[] {1, 2, 3};.
•	The new keyword trap: Writing int[] arr3; only creates a name tag (pointer). It doesn't actually create memory space. You must use new to build it, like: int[] arr3 = new int[1000];.
•	Wrong Syntax to Avoid: Writing int[11] arr6; will give an error. Always put the size on the right side: int[] arr6 = new int[11];.
4. Loop Tricks and Arrow Shortcuts
•	n++ vs ++n:
o	arr[n++] uses the index n first, and then adds 1 to n.
o	arr[++n] adds 1 to n first, and then uses that new number as the index.
•	continue; $\rightarrow$ Skips the rest of the code inside the loop just for this round and jumps straight to the next loop step.
•	break; $\rightarrow$ Completely stops the loop and jumps all the way out of it.
•	The "Does Not Exist" Error: If your computer says error CS0103: 'i' does not exist in the current context, it means you are trying to use a variable outside the curly braces {} where it was born.
•	Two Dots .. (Slicing): Used to chop arrays into smaller pieces quickly (Example: nums[..mid] means from the start up to the middle).
5. Safe Input (int.TryParse)
•	Why int.Parse is dangerous: If you use int.Parse(Console.ReadLine()) and the user accidentally types a word like "abc" or leaves it blank, the program instantly crashes.
•	Why int.TryParse is safe: It converts text to a number safely without crashing. It does two things at once:
1.	It checks if the text is a valid number and gives back a True or False.
2.	If it is valid, it saves the final number into an out variable.
•	What works: "10", "0", "-5" (negative numbers are allowed), and " 25 " (spaces on the outside are ignored).
•	What crashes/fails: "abcd", "12.5" (decimals fail an integer check), and "" (empty text).
•	The Exclamation Mark ! Trick: Putting ! in front of it (like !int.TryParse(...)) means "If this is NOT a valid number, run the code inside."
6. Searching and Chopping Words
•	s.Split(' ') $\rightarrow$ Chops up a long string into an array of separate words using spaces. If you add StringSplitOptions.RemoveEmptyEntries, it safely throws away any double or accidental blank spaces.
•	Array.IndexOf(arr, item, start, count) $\rightarrow$ Looks inside an array to find where an item is hiding. It tells you the exact index number. If it can't find it, it returns -1.
•	Array.LastIndexOf(arr, 10) $\rightarrow$ Searches backwards from the end of the array to find where the number 10 last appeared.

2. Value Types vs. Reference Types (Memory Layout) 🧠
This matches perfectly with the "Pass by Value vs. Reference" concept we talked about for JavaScript, but C# has explicit names for where these live in your computer's hardware.
•	The Stack (Value Types): Super fast, temporary storage. Simple types like int, double, bool, and char live here. When a function ends, they are instantly popped off and destroyed.
•	The Heap (Reference Types): Larger, managed memory space. Complex things like Arrays, Lists, and Class Objects live here.
•	The Pointer Trap: When you write int[] arr;, the name tag arr lives on the Stack, but it stays empty (null) until you use new int[5], which carves out the actual data boxes on the Heap.
________________________________________
3. Collections and Type Parameters (<T>) 🗃️
You noted HashSet<int> and List<T>. The <T> stands for Generic Type. It means the collection enforces strict rules on what is allowed inside.
•	List<T>: Keeps things in a strict, indexed order (0, 1, 2...). It allows duplicates.
•	HashSet<T>: A chaotic bag with no fixed order, but it has a superpower: It completely forbids duplicates. If you try to add the number 5 twice, it silently ignores the second one. It is lightning-fast for checking if an item exists using .Contains().

1. The Modern Way: System.Collections.Generic 🚀 (What you use now)
This is the toolbox that contains List<T> and HashSet<T>. The word Generic means you must specify the exact data type using the angle brackets < >.
•	Once you say List<int>, that list is strictly locked to integers. You cannot accidentally slide a string or a decimal inside it. It is completely safe and lightning-fast.
________________________________________
2. The Old Way: System.Collections 📜 (The Legacy Trap)
If you leave off the word .Generic at the top of your file and just import System.Collections, you are opening up C#'s old, historic toolbox from twenty years ago.
This toolbox contains old data structures like ArrayList and Hashtable.
•	The Catch: These old collections do not use angle brackets < >. They allow you to mix and match any data type together in the same bag. You could put a number, a string, and a character all inside the same ArrayList.

SECTION 1: SYSTEM.COLLECTIONS.GENERIC (The Data Containers)
-------------------------------------------------------------------
In C#, plain arrays are a fixed size. To use dynamic memory boxes 
that grow and shrink, you MUST write "using System.Collections.Generic;" 
at the very top of your code file.

1. List<T> ➡️ The Ordered Sequence
   - What it is: A dynamic array that manages its own size.
   - Ordering: Strict index positions (0, 1, 2, 3...).
   - Duplicates: 🟢 ALLOWED. You can store the same value multiple times.
   - Code Sample:
     List<int> scores = new List<int>();
     scores.Add(90);
     scores.Add(90); // 🟢 Works! Now holds [90, 90]
     int firstScore = scores[0]; // Fast lookup via index

2. HashSet<T> ➡️ The Unique Bag
   - What it is: A chaotic mathematical collection with NO fixed order.
   - Ordering: ❌ NONE. You cannot use index numbers like hashSet[0].
   - Duplicates: ❌ FORBIDDEN. It completely blocks duplicate values.
   - Superpower: It is lightning-fast for checking if an item exists 
     using .Contains().
   - Code Sample:
     HashSet<int> playerIds = new HashSet<int>();
     playerIds.Add(101);
     playerIds.Add(101); // ❌ Silently ignored! Only contains one 101.
     bool hasPlayer = playerIds.Contains(101); // 🟢 True (Instant lookup)

SECTION 2: SYSTEM.LINQ (Language Integrated Query)
-------------------------------------------------------------------
LINQ is C#'s data-searching engine. It allows you to sort, filter, 
and transform data inside arrays, Lists, or HashSets using clean, 
one-line arrow expressions (`=>`).

🌟 THE BIG RULE: LINQ methods do NOT modify your original list. 
   They return a fresh query sequence. You must attach `.ToList()` 
   or `.ToArray()` at the end to save it back into a concrete variable!

1. .Where() ➡️ The Filter (JavaScript equivalent: .filter())
   - What it does: Extracts only items that pass a true/false condition.
   - Code Sample:
     int[] nums = { 1, 2, 3, 4, 5, 6 };
     var evens = nums.Where(n => n % 2 == 0).ToList();
     // evens becomes [2, 4, 6]

2. .Select() ➡️ The Transformer (JavaScript equivalent: .map())
   - What it does: Steps through every item and transforms it into 
     something new.
   - Code Sample:
     int[] prices = { 10, 20, 30 };
     var doublePrices = prices.Select(p => p * 2).ToArray();
     // doublePrices becomes [20, 40, 60]

3. .Any() ➡️ The Quick Match Check (JavaScript equivalent: .some())
   - What it does: Returns a single `true` or `false`. Checks if at 
     least ONE item matches your condition.
   - Code Sample:
     List<int> ages = new List<int> { 15, 18, 21 };
     bool hasAdults = ages.Any(a => a >= 18); 
     // 🟢 Returns True (because of 18 and 21)

4. .All() ➡️ The Absolute Rule Check (JavaScript equivalent: .every())
   - What it does: Returns `true` ONLY if every single item in the 
     list passes the condition.
   - Code Sample:
     List<int> balances = new List<int> { 50, 100, -5 };
     bool allPositive = balances.All(b => b > 0);
     // ❌ Returns False (because of -5)

5. .First() / .FirstOrDefault() ➡️ The Target Grabber
   - What it does: Searches the list and pulls out the very first matching 
     element it encounters.
   - CRITICAL TEST TRAP: If you use `.First()` and no item matches your 
     search, your program instantly CRASHES! 
     Always use `.FirstOrDefault()` instead—if nothing matches, it safely 
     returns `0` for numbers or `null` for objects instead of crashing.
   - Code Sample:
     int[] stock = { 5, 12, 8, 20 };
     int highStock = stock.FirstOrDefault(s => s > 10);
     // highStock becomes 12 (it completely ignores 20 because 12 came first)
