?? "0" (The Null-Coalescing Operator)
This is a safety net. It says: "If the stuff on the left is null, use the string "0" on the right instead".

This removes the "Possible null reference" green squiggle you were seeing in image_e177b1.png because it guarantees that a string (even if it's just "0") is passed forward.

int.Parse(...)
This takes that string (like "10" or our safety "0") and converts it into an actual integer number that you can use for math or logic (like n1 > n2).

2. int.TryParse(..., out int n1)

Ah, the classic Visual Studio clutter! Don't worry, your file hasn't actually vanished from the planet.

What is happening here is that Visual Studio's background worker files (everything inside that hidden `.vs` folder) are constantly changing, deleting, and recreating themselves while you write code. Because Git is tracking *everything* right now, your terminal is flooded with red text, masking what's actually happening.

Also, if you are switching branches using `git checkout` or `git switch`, Git will physically swap out the files in your folder to match whatever that specific branch looks like. If you created a file on Branch A but didn't commit it, and then switched to Branch B, it might look like it disappeared!

Here is how to get your files stable, clean up this mess, and keep everything intact:

### Step 1: Hide the Visual Studio Noise (`.gitignore`)

You never want to track the `.vs` folder in Git. Let's tell Git to ignore it completely so you only see your actual C# files.

1. Open your terminal in that `CodingPractise` folder.
2. Create a file named `.gitignore` by running:
```bash
echo .vs/ >> .gitignore

```


3. Run `git status` again. You'll see almost all that red text disappear instantly, leaving only your actual code changes (like `Program.cs`).

### Step 2: Make Sure Your New File is Saved to the Branch

Right now, your terminal shows:

* `new file: CsharpPrograms/StringToInteger(Atoi).cs` is green (staged and safe).
* `modified: CsharpPrograms/Program.cs` is red (unstaged).

Before you switch branches or do anything else, **lock these in** so they can't disappear when you move around. Run these commands:

```bash
# 1. Add any remaining changes (like Program.cs)
git add .

# 2. Save a permanent snapshot to your current branch
git commit -m "Save Atoi program and Program.cs changes"

```

### Step 3: Traveling Between Branches Safely

Now that you have committed your work, it is safe in the history of the `StringToInteger` branch.

* If you switch back to `main` or `master`, the `StringToInteger(Atoi).cs` file **will disappear** from your Windows folder. **This is normal!** Git does this because that file doesn't exist on the main branch yet.
* To bring it back instantly, just switch back to your feature branch:
```bash
git switch StringToInteger

```



Once you add that `.gitignore` file and commit your progress, you won't have to worry about files vanishing into thin air anymore!
