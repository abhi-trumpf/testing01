SECTION 1: C# RULES & SYNTAX NOTES
(How to write the code correctly so it doesn't crash)

Spelling and Capital Letters (C# is very strict)
• .Length -> Always use a capital L. Never put brackets after it like .Length(). It counts things in any array (int[], char[]), not just words.
• Console.ReadLine() -> Capital C, R, and L. This is used to take what the user types.
• Console.Write() vs Console.WriteLine() -> Capital C, W, and L.

Console.Write() prints text and keeps the typing cursor on the same line.

Console.WriteLine() prints text and moves the cursor to the next line.
• HashSet -> Always capitalize the S (HashSet).
• Main -> The starting point of your program must be written exactly like this: public static void Main(string[] args). The M must be capital, and the square brackets [] go right next to the word string.

Simple Text & Math Rules
• No let keyword -> You cannot use let like in JavaScript. You must say the real type, like int rem = 0;.
• String Interpolation ($"") -> Putting a $ before your text lets you inject variables, but only if you put curly braces {} around the variable name.

Wrong: Console.WriteLine($"lcm is", max); (This completely ignores max).

Right: Console.WriteLine($"lcm is {max}");
• Modulo Math Reminder -> When you divide a smaller number by a bigger number using %, the answer is just the smaller number itself (Example: 1 % 10 = 1).

Working with Arrays and Lists
• The Big Difference:

An Array (int[]) is a fixed size. Once you make it, you cannot grow it. You cannot use shortcuts like .Add() or .Remove().

A List (List) is dynamic. It can grow and shrink whenever you want. You must write "using System.Collections.Generic;" at the top of your file to use it.
• Making Arrays (New vs Old C#):

C# 12 or newer: You can use clean square brackets: int[] arr = [1, 2, 3];.

C# 11 or older: You must use curly braces: int[] arr = {1, 2, 3}; or new int[] {1, 2, 3};.
• The new keyword trap: Writing int[] arr3; only creates a name tag (pointer). It doesn't actually create memory space. You must use new to build it, like: int[] arr3 = new int[1000];.
• Wrong Syntax to Avoid: Writing int[11] arr6; will give an error. Always put the size on the right side: int[] arr6 = new int[11];.

Loop Tricks and Arrow Shortcuts
• n++ vs ++n:

arr[n++] uses the index n first, and then adds 1 to n.

arr[++n] adds 1 to n first, and then uses that new number as the index.
• continue; -> Skips the rest of the code inside the loop just for this round and jumps straight to the next loop step.
• break; -> Completely stops the loop and jumps all the way out of it.
• The "Does Not Exist" Error: If your computer says error CS0103: 'i' does not exist in the current context, it means you are trying to use a variable outside the curly braces {} where it was born.
• Two Dots .. (Slicing): Used to chop arrays into smaller pieces quickly (Example: nums[..mid] means from the start up to the middle).

Safe Input (int.TryParse)
• Why int.Parse is dangerous: If you use int.Parse(Console.ReadLine()) and the user accidentally types a word like "abc" or leaves it blank, the program instantly crashes.
• Why int.TryParse is safe: It converts text to a number safely without crashing. It does two things at once:

It checks if the text is a valid number and gives back a True or False.

If it is valid, it saves the final number into an out variable.
• What works: "10", "0", "-5" (negative numbers are allowed), and " 25 " (spaces on the outside are ignored).
• What crashes/fails: "abcd", "12.5" (decimals fail an integer check), and "" (empty text).
• The Exclamation Mark ! Trick: Putting ! in front of it (like !int.TryParse(...)) means "If this is NOT a valid number, run the code inside."

Searching and Chopping Words
• s.Split(' ') -> Chops up a long string into an array of separate words using spaces. If you add StringSplitOptions.RemoveEmptyEntries, it safely throws away any double or accidental blank spaces.
• Array.IndexOf(arr, item, start, count) -> Looks inside an array to find where an item is hiding. It tells you the exact index number. If it can't find it, it returns -1.
• Array.LastIndexOf(arr, 10) -> Searches backwards from the end of the array to find where the number 10 last appeared.

SECTION 2: OBJECT-ORIENTED PROGRAMMING (OOP) BASICS
• Constructors: Special methods used to build an object. They have the exact same name as the class and no return type.
• Destructors: Written with a tilde (~MyClass()), used to clean up memory right before the object is destroyed.
• The this Keyword in C#: Unlike JavaScript's dynamic context, this in C# is incredibly stable. It only ever means "the current instance of this specific class."

SECTION 3: VALUE TYPES VS. REFERENCE TYPES (Memory Layout)
• The Stack (Value Types): Super fast, temporary storage. Simple types like int, double, bool, and char live here. When a function ends, they are instantly popped off and destroyed.
• The Heap (Reference Types): Larger, managed memory space. Complex things like Arrays, Lists, and Class Objects live here.
• The Pointer Trap: When you write int[] arr;, the name tag arr lives on the Stack, but it stays empty (null) until you use new int[5], which carves out the actual data boxes on the Heap.

SECTION 4: COLLECTIONS & NAMESPACES (Modern vs Old)
The Modern Way: System.Collections.Generic (Strict Type Safety)
This is the toolbox that contains List and HashSet. The word Generic means you must specify the exact data type using the angle brackets < >.

Once you say List, that list is strictly locked to integers. You cannot slide a string inside it. It is completely safe and fast.

The Old Way: System.Collections (The Legacy Trap)
If you leave off the word .Generic at the top of your file, you open up C#'s old, historic toolbox from twenty years ago. This contains structures like ArrayList and Hashtable.

The Catch: These structures do not use angle brackets < >. They allow you to mix and match any data type together in the same bag (ints, strings, chars mixed). It is slow, unsafe, and causes boxing errors.

Collection Mechanics:
• List -> The Ordered Sequence

Ordering: Strict index positions (0, 1, 2, 3...).

Duplicates: ALLOWED. You can store the same value multiple times.
• HashSet -> The Unique Bag

Ordering: NONE. You cannot use index numbers like hashSet[0].

Duplicates: FORBIDDEN. It completely blocks duplicate values.

Superpower: It is lightning-fast for checking if an item exists using .Contains().

SECTION 5: SYSTEM.LINQ (Language Integrated Query)
LINQ is C#'s data-searching engine. It allows you to sort, filter, and transform data inside arrays, Lists, or HashSets using clean, one-line arrow expressions (=>).

🌟 THE BIG RULE: LINQ methods do NOT modify your original list. They return a fresh query sequence. You must attach .ToList() or .ToArray() at the end to save it back into a concrete variable!

.Where() -> The Filter (JavaScript equivalent: .filter())

Extracts only items that pass a true/false condition.

Example: int[] nums = { 1, 2, 3, 4, 5, 6 };
var evens = nums.Where(n => n % 2 == 0).ToList(); // [2, 4, 6]

.Select() -> The Transformer (JavaScript equivalent: .map())

Steps through every item and transforms it into something new.

Example: int[] prices = { 10, 20, 30 };
var doublePrices = prices.Select(p => p * 2).ToArray(); // [20, 40, 60]

.Any() -> The Quick Match Check (JavaScript equivalent: .some())

Returns a single true or false. Checks if at least ONE item matches your condition.

Example: List ages = new List { 15, 18, 21 };
bool hasAdults = ages.Any(a => a >= 18); // True

.All() -> The Absolute Rule Check (JavaScript equivalent: .every())

Returns true ONLY if every single item in the list passes the condition.

Example: List balances = new List { 50, 100, -5 };
bool allPositive = balances.All(b => b > 0); // False

.First() / .FirstOrDefault() -> The Target Grabber

Searches the list and pulls out the very first matching element it encounters.

CRITICAL TEST TRAP: If you use .First() and no item matches your search, your program instantly CRASHES! Always use .FirstOrDefault() instead—if nothing matches, it safely returns 0 for numbers or null for objects.

Example: int[] stock = { 5, 12, 8, 20 };
int highStock = stock.FirstOrDefault(s => s > 10); // 12

Once you create a `StringBuilder` instance, it comes packed with a fantastic set of built-in tools to manipulate your text. Here are the main ones you'll use all the time:

---

### 1. `.AppendFormat()`

Like `.Append()`, but it lets you slide variables directly into the text using placeholders, exactly like `Console.WriteLine` or string interpolation.

```csharp
sb.AppendFormat("User {0} logged in at {1}.", "Abhishek", "3:30 PM");
// Result: "User Abhishek logged in at 3:30 PM."

```

### 2. `.AppendLine()`

This appends your text and automatically throws a **new line** (Enter key) onto the end of it. It saves you from manually typing `\n`.

```csharp
sb.AppendLine("Line 1");
sb.AppendLine("Line 2");

```

### 3. `.Insert()`

This lets you shove characters or words into the *middle* of your text at a specific index, pushing everything else to the right.

```csharp
StringBuilder sb = new StringBuilder("I C#");
sb.Insert(2, "love "); 
// Result: "I love C#"

```

### 4. `.Remove()`

The opposite of insert. You give it a starting index and tell it exactly how many characters to delete.

```csharp
StringBuilder sb = new StringBuilder("Hello World");
sb.Remove(5, 6); // Starts at index 5, deletes 6 characters
// Result: "Hello"

```

### 5. `.Replace()`

This acts exactly like "Find and Replace" in Microsoft Word. It swaps out every single instance of a specific letter or word with a new one.

```csharp
StringBuilder sb = new StringBuilder("sadbutsad");
sb.Replace("sad", "happy");
// Result: "happybuthappy"

```

### 6. `.Clear()`

Completely wipes the slate clean, resetting the `StringBuilder` back to an empty state without you having to destroy the variable and recreate it.

```csharp
sb.Clear(); // Empties everything out

```

---

### The Final Step: `.ToString()`

Don't forget this one! While the loop is running, the computer stores everything inside a special `StringBuilder` format. When you are completely done and want to hand the final text over to a normal string or a `Console.WriteLine`, you call:

```csharp
string finalResult = sb.ToString();
```

This is one of the coolest parts of dealing with strings in C#. You are basically looking at a **grid** (or a 2D structure), even though it’s just an array of text.

Here is the exact breakdown of how your code switches between grabbing an **entire word** and grabbing an **individual character**.

---

### 1. How you access the singular words

An array of strings (`string[] x`) is a collection where each slot holds a full word. You access them using a **single index** `[i]`.

* `x[0]` gives you the full string `"flower"`
* `x[1]` gives you the full string `"flow"`
* `x[2]` gives you the full string `"flight"`

When your loop runs `string CurrentWord = x[i];`, it is pulling the entire text out of that array slot and storing it.

---

### 2. How you access the individual characters

Here is the secret: **In C#, a `string` is secretly just an array of characters (`char`).** Because a string is already an array under the hood, you can put a second index `[j]` right next to a string variable to pull out a single letter.

Inside your inner loop, you have two string variables: `prefix` (which is `"flower"`) and `CurrentWord` (which is `"flow"`). To compare them letter-by-letter, you use the `j` index:

* `prefix[j]` $\rightarrow$ If $j = 0$, this is `'f'`. If $j = 1$, this is `'l'`.
* `CurrentWord[j]` $\rightarrow$ If $j = 0$, this is `'f'`. If $j = 1$, this is `'l'`.

---

### Visualizing the Grid 🗺️

Think of your data like this grid. The `i` loop chooses the **row** (the word), and the `j` loop chooses the **column** (the character):

| Index `j` (Characters) | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| **`x[0]` (prefix)** | 'f' | 'l' | 'o' | 'w' | 'e' | 'r' |
| **`x[1]` (CurrentWord)** | 'f' | 'l' | 'o' | 'w' |  |  |
| **`x[2]`** | 'f' | 'l' | 'i' | 'g' | 'h' | 't' |

### How you would write it inside the loop

To actually compare the individual characters inside that inner `j` loop, you just use the variables with their index like this:

```csharp
for (int j = 0; j < prefix.Length && j < CurrentWord.Length; j++) 
{
    // Accessing individual characters!
    if (prefix[j] == CurrentWord[j]) 
    {
        // If the letters match, add it to your temporary prefix
        TempPrefix += prefix[j]; 
    }
    else 
    {
        // As soon as a letter doesn't match, stop looking at this word
        break; 
    }
}

```

* **Single index `x[i]**` = Pulls the whole word out of the box.
* **Double indexing/String index `CurrentWord[j]**` = Reaches inside that specific word to grab a single letter.

You don't use git merge to create the commit; you use it to combine two branches that already have commits.

Think of it like this:

git commit (Saving a snapshot): While you are working on your <branchname> branch, you use git add and git commit to save your progress. This locks your changes safely into that specific branch.

git merge <branchname> (Combining the timelines): Once those changes are committed and safe on your branch, you switch to main and run the merge. Git looks at the snapshots you saved on <branchname> and cleanly copies/integrates them into main.

So the exact flow is:
