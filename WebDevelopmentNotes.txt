================================================================================
                    GET VS POST FOR THE STATIC TEMPLATE
================================================================================

Not always! That static HTML template actually plays a role in BOTH types of 
requests, but it does a completely different job depending on the method.

Here is the exact breakdown of how that static file is used:

[1] WHEN IT IS A GET REQUEST (Loading the Page)
--------------------------------------------------------------------------------
* Meaning: The user typed your URL into the browser or clicked a "Home" link.
* The Action: Python reads the static template file, sees no form data to 
  process, and sends it over as a clean, blank starting slate.
* Result: The user sees an empty form waiting for inputs.


[2] WHEN IT IS A POST REQUEST (Submitting the Form)
--------------------------------------------------------------------------------
* Meaning: The user filled out the form fields and clicked the submit button.
* The Action: Python intercepts the incoming data, talks to the SQL database, 
  and then opens that exact same static HTML template file.
* Result: Python uses the template as a factory blueprint. It loops through 
  the file, injects the new live database results into the Jinja placeholders, 
  and hands the newly built webpage back to the user.

================================================================================
                           TRAFFIC MANAGEMENT DIAGRAM
================================================================================

  USER ACTION                        REQUEST METHOD    SERVER SEES TEMPLATE AS:
  ------------------------------------------------------------------------------
  Clicks link / Loads site     -->   GET          -->  A blank form to display.
  Hits "Submit" button         -->   POST         -->  A factory blueprint to 
                                                       fill with database data.

================================================================================

They are HTTP request methods (also commonly called HTTP verbs).

When you use GET, the data is pasted right on the outside of the envelope for everyone to see. When you use POST, the data is sealed inside the envelope.

GET is a Postcard: The mail carrier, the sorting facility workers, and anyone looking at your desk can read what is written on it.
->Goes to the page and renders the page

POST is a Sealed Letter: People can see who it is addressed to (the URL), but they have to tear open the envelope to see the message inside.

GET - read only

POST - write and modify the data

Method   CRUD Action   Database Op      Safe?* Idempotent?** Privacy Level
------   -----------   -----------      ------   -------------   -------------

POST --> CREATE    --> Insert Record    NO       NO              HIGH (Sealed)

function countCharacters(s) {
    // 1. FRESH CONTAINER
    // Defining inside the function so it flushes/resets for every new input string.
    // We use an object literal because it acts as a dictionary to hold key-value pairs.
    let result = {};  

    // 2. THE ITERATION
    for (let item of s) {
        
        // IMPORTANT SYNTAX: Check if the counter for that particular char already exists
        if (result[item]) {
            // If character exists, increment its unrelated independent count
            result[item] = result[item] + 1;
        } 
        else {
            // If character is seen for the first time, initialize it to 1
            result[item] = 1;
        }
    }

    return result;
}

# A SQL Database and a JavaScript Object never talk directly to each other.

# and reside on different machines.

# 2. THE DATA TRANSFORMATION TIMELINE:

# STEP A: THE SQL DATABASE (The Warehouse)
# - Data lives as raw tables (rows/columns) on the storage disk.
# - Database spits out a raw row tuple: (101, "Diyaa")

# STEP B: THE PYTHON SERVER / FLASK (The Translator)
# - Flask catches that raw tuple using its database driver.
# - Flask converts that tuple into a Python Dictionary: {"id": 101, "name": "Diyaa"}
# - Flask serializes (converts) that dictionary into a raw JSON text string: '{"id": 101, "name": "Diyaa"}'
# - Flask spits that JSON string over the network network to the browser.

# - The browser receives the raw JSON text string.
# - JavaScript parses (translates) that text string back into a native JavaScript Object: { id: 101, name: "Diyaa" }
# - JS can now dynamically manipulate the UI with it.


# 3. THE COMPLETE VISUAL STREAM PIPELINE:

[1] WEB SITE (Informational)
--------------------------------------------------------------------------------
* Description  : Primarily informational. It is meant to be read, viewed, or 
                 listened to, but you don't really change anything on the page.

* Primary Goal : To deliver information to the user.

* Examples     : - A restaurant's page showing their menu and hours.
                 - A personal portfolio or blog.
                 - A news website (like BBC or CNN) where you just read articles.

[2] WEB APPLICATION (Interactive)
--------------------------------------------------------------------------------
* Description  : Highly interactive and dynamic. It behaves like software you 
                 would install on your computer, but it runs inside your browser. 
                 It takes inputs from you, processes data, performs actions, and 
                 updates the page without you needing to constantly refresh it.
* Primary Goal : To help the user perform a specific task or function.
* Interaction  : High. You create accounts, type data, manipulate elements, and 
                 get customized results based on your actions.
* Examples     : - Google Tasks / Calendar: You add, delete, and move items.
                 - GitHub: You host code, open pull requests, and review changes.
                 - Online Games: Dynamic, real-time interactivity.

* Meaning : This is the URL path or destination where the form data should be 
            sent when the user clicks the "Submit" button.
* Value   : "/" means the root or main home page route of your current server. 
            If it said "/submit-login", it would send the data to that specific 
            login page backend route.


[2] method="post"  -->  REQUEST METHOD (The "How")
--------------------------------------------------------------------------------
* Meaning : This tells the browser what type of HTTP action to use when sending 
            the data. 
* Type    : "post" is used when you want to securely *send* or *create* data on 
            a server (like submitting a password, creating a poll answer, or 
            adding a new task). The data is packaged up secretly inside the 
            request body, hidden from the URL bar.

In Python, your database returns data that looks like this:

Python
birthdays = [
    {"name": "Harry", "month": 7, "day": 31},
    {"name": "Hermione", "month": 9, "day": 19}
]
To display this list of dictionaries on your HTML side, you combine the Action Brackets {% %} to loop through the list, and the Print Brackets {{ }} to pull the values out of the dictionaries using dot notation (variable.key).

The HTML Blueprint
Here is how you write it inside your HTML file:

HTML
<table>
    <thead>
        <tr>
            <th>Name</th>
            <th>Birthday</th>
        </tr>
    </thead>
    <tbody>
        {% for row in birthdays %}
        <tr>
            <td>{{ row.name }}</td>
            <td>{{ row.month }}/{{ row.day }}</td>
        </tr>
        {% endfor %}
    </tbody>
</table>
How Jinja Processes This Behind the Scenes
Plaintext
================================================================================
                         JINJA DICTIONARY UNWRAPPING
================================================================================

 The Python List:   [ {"name": "Harry", ...}, {"name": "Hermione", ...} ]
                              |                         |
                              v                         v
                       1st Loop Cycle            2nd Loop Cycle
                       row = 1st dict            row = 2nd dict

--------------------------------------------------------------------------------

 How the values are extracted:
 
   {{ row.name }}   ----> Looks at the current dictionary, finds the "name" key
   {{ row.month }}  ----> Looks at the current dictionary, finds the "month" key

================================================================================


================================================================================
                           JINJA LOOP BOUNDARY RULES
================================================================================

{% for row in birthdays %}  ---> [START SIGN]: Start looping here.
                                 Every HTML element inside this middle zone 
                                 will be duplicated and printed over and over 
                                 for every single dictionary in your list.
                                 
{% endfor %}                 ---> [STOP SIGN]: Stop looping right here.
                                 The loop breaks out immediately. Anything typed
                                 below this marker will only appear ONCE on 
                                 your website, no matter how many birthdays 
                                 are in your database.

================================================================================


Yes, exactly! It is purely a Start and Stop system for Jinja.

Because HTML does not have loops or indentation rules like Python, Jinja uses 
these explicit markers to know exactly where the boundary begins and ends:

* {% for ... %}  --> Start looping/repeating from this exact spot.
* {% endfor %}    --> Stop looping right here and go back to normal.



The Function (The Worker): This is a basic piece of code that does one specific job, like making a webpage that says "Hello World!". By itself, it’s just sitting there waiting to be told what to do.
The Decorator (The Connector): This is the bridge. It takes your function and hooks it up to Flask. For example, @app.route('/home') is a decorator that tells Flask, "Hey, look at this worker function right here!"
Flask (The Boss): When Flask starts up, the decorators hand it all the functions. Flask keeps a master list.
